# Создание моделей Supreme Commander: Forged Alliance / FAF

Локальный рабочий процесс на основе турели GGA2301, пересобранной по референсу
20 октября 2026 года. Начинай с этого документа и исходников примера. Интернет
нужен для отсутствующих сведений, противоречий, новых версий инструментов или
по прямой просьбе пользователя. Приведённые размеры и художественные решения
относятся к GGA2301; они не являются общими требованиями к юнитам FAF.

## 1. Инструменты и локальный пример

Для проверенного процедурного процесса достаточно Python, numpy и Pillow.
`math`, `struct`, `pathlib` и другие стандартные модули входят в Python.
Python создаёт настоящие SCM/SCA/DDS; изображения предпросмотра служат для оценки
этих файлов и не заменяют игровую модель.

На момент записи использовались Python 3.12.14, numpy 2.3.5, Pillow 12.3.0.
Это сведения о рабочем окружении, а не обязательная фиксация зависимостей.
Доступный локальный интерпретатор:

```powershell
$modelPython = 'C:\Users\Nestr\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $modelPython -c "import sys, numpy, PIL; print(sys.executable); print(numpy.__version__, PIL.__version__)"
```

Если путь изменился, найди доступный Python локально или через инструмент
`load_workspace_dependencies`. Не начинай с поиска новых программ в Интернете.
Если используется отдельный Python без библиотек, зависимости — `numpy` и `Pillow`;
устанавливать Blender для запуска существующего генератора не требуется.

Основные файлы находятся в
[`mods/seraphim-rework/source-assets/GGA2301/`](../mods/seraphim-rework/source-assets/GGA2301/):

| Файл | Назначение |
| --- | --- |
| `generate_prism_spire.py` | Точка входа, имена костей, иерархия, опорные координаты, анимации, сборка LOD |
| `prism_reference_model.py` | Геометрия, UV, атлас материалов, нормали, OBJ и рендер экспортированного SCM |
| `supcom_binary.py` | Запись SCM v5, SCA v5 и DDS DXT5/BC3 с mip-уровнями |
| `reference-2026-10-20.png` | Изображение, по которому построена модель |
| `GGA2301_source.obj`, `.mtl` | Редактируемая геометрия, UV, нормали и группы с именами костей |
| `GGA2301_*_source.png` | Исходные карты материалов без DDS-сжатия |
| `GGA2301_reference_rebuild_views.png` | Фронтальный, боковой и верхний ракурсы |
| `README.md` | Координаты и особенности именно этой турели |
| `archive/before-reference-rebuild-2026-10-20/` | Предыдущая рабочая версия |

OBJ/MTL не сохраняют полноценный скелет и анимации. Имена групп помогают заново
привязать геометрию в редакторе, но не заменяют armature и SCA.

Сборка существующей турели из корня рабочего пространства:

```powershell
& $modelPython 'mods\seraphim-rework\source-assets\GGA2301\generate_prism_spire.py'
```

Команда перезаписывает модель, анимации и текстуры GGA2301 в рабочей копии мода.
Перед экспериментами сохрани нужную версию в `source-assets/<unit-id>/archive/`.
Не запускай генератор только ради редактирования документации.

Blender полезен для ручного моделирования, UV, редактирования OBJ и создания
сложного скелета. В этой сборке он не устанавливался и не запускался. Исторический
экспортёр Oygron описан для Blender 2.71–2.73: его совместимость с современным
Blender нельзя предполагать. Для нового редактора/аддона сначала установи его
реальную совместимость. Готовые локальные писатели форматов позволяют обойтись
без Blender при создании моделей этого типа.

## 2. Сначала геометрия и сходство с референсом

1. Сохрани референс внутри исходников соответствующего мода. Выдели основание,
   опоры, основные дуги, проёмы, центральный узел, оружие и подвижные части.
2. Зафиксируй пропорции: высоту к ширине, уровни крупных деталей, толщину рамок,
   размеры и положение пустого пространства. Невидимые стороны восстанови
   согласованно, например симметрией, и запиши это предположение.
3. Собери силуэт. Для органических стоек используй сечения вдоль кривой,
   объёмные рёбра и фаски; для колец — кольцевую геометрию с внутренним отверстием.
   Проёмы должны быть настоящими отверстиями, стойки — иметь толщину.
4. Сравни фронтальный, боковой и игровой верхний ракурсы. Исправляй форму до
   добавления мелких узоров: текстуры не исправляют неверные пропорции.
5. Добавь слои брони, механизмы, кромки и световые вставки. Затем назначь материалы.
   Для Seraphim используй заданный пользователем стиль: блестящий серебристый
   металл, отражающие металлические рамки и плавные линии цвета игрока.
   Опоры могут быть темнее, но должны оставаться металлическими.
6. Сделай упрощённый LOD: уменьши число сечений и сегментов колец, убери мелкие
   вставки. Сохраняй силуэт, имена костей и опорные координаты во всех LOD.

В примере LOD0 содержит 11 312 треугольников / 33 936 записей вершин, LOD1 —
5 508 / 16 524. Это результат конкретной модели, не рекомендуемый бюджет для всех
юнитов. Учитывай число таких юнитов в матче; уменьшай детализацию при необходимости.
Писатель дублирует вершины по треугольникам, поэтому учитывай число экспортированных
записей, а не только уникальные точки поверхности.

## 3. Координаты, скелет и точка выстрела

В локальном генераторе Y направлена вверх, +Z — вперёд. Вершины и скелет сразу
создаются в игровых осях. Не добавляй к ним ещё одно преобразование осей из
экспортёра Blender. Масштаб задаётся через `Display.UniformScale`; у GGA2301 он 0.06,
то есть 22 единицы исходника соответствуют 1.32 игровой единицы.

Используй один скелет с корневой костью по идентификатору юнита. Все вершины должны
быть привязаны к существующей кости. Для текущего писателя каждая вершина жёстко
привязана к одной кости; плавные веса между несколькими костями не реализованы.
Исходные повороты костей равны единичному quaternion, а позиции заданы локально
относительно родителя. Эти ограничения относятся к писателю, а не ко всему движку.

Иерархия оружия в примере:

```text
GGA2301
├── Turret                 поворот по горизонтали
│   └── Turret_Barrel       наклон оружия
│       └── Turret_Muzzle   точка выпуска луча
├── Halo                   кристалл
├── FinLeft
├── FinRight
└── FinRear
```

Размещай `Turret_Muzzle` непосредственно перед выпускным отверстием, учитывая
масштаб и положение родителей. Сверяй её имя с `RackBones[].MuzzleBones` и
`TurretBoneMuzzle` в blueprint, а кости наведения — с `TurretBoneYaw` и
`TurretBonePitch`. Для оружия с другой схемой используй его собственную иерархию.

Для нескольких разнесённых по высоте стволов не привязывай все их вершины к
одной pitch-кости: они будут вращаться вокруг общего центра и покидать платформы.
В GGA2401 каждому стволу задан собственный шарнир под отдельным `Island_*`;
четыре шарнира следуют за основным через `CreateSlaver(self, slaveBone, masterBone)`.
Этот вызов подтверждён локальным штатным `units/UAL0205/UAL0205_script.lua`;
контроллер добавляется в `Trash`. Сами островки не подчинены pitch-костям.
Геометрия и зазоры GGA2401 проверены по SCM, наведение этой версии в игре пока
не проверено.

У GGA2301 `Turret` находится в `(0, 22, 0)`, `Turret_Barrel` — в `(0, 0, 0)`
относительно него, `Turret_Muzzle` — в `(0, 0, 6.65)` относительно ствола.
При нулевом наведении выпуск расположен на высоте 1.32 и вынесен вперёд на 0.399
игровой единицы. Проверь его положение и при крайних углах наклона; одна высокая
координата в исходной позе не гарантирует отсутствия пересечения с землёй.

## 4. Запись SCM v5

Предпочитай уже проверенный `supcom_binary.py` новому ручному писателю.
Он создаёт треугольную сетку со следующими структурами, little-endian:

| Часть | Формат / размер |
| --- | --- |
| Заголовок | `<4s11I`, 48 байт, сигнатура `MODL`, версия 5 |
| Запись кости | `<16f3f4f4i`, 108 байт |
| Запись вершины | `<16f4B`, 68 байт |
| Индексы треугольников | `uint16`, три индекса на треугольник |

В кости записаны обратная абсолютная bind-матрица, локальная позиция, quaternion
в порядке `(w, x, y, z)`, смещение имени, индекс родителя и служебные поля.
В вершине — позиция, нормаль, tangent, bitangent, два UV-набора и индексы костей.
В этой реализации UV-наборы совпадают; используется первый индекс кости.

Секции имеют метки `NAME`, `SKEL`, `VTXL`, `TRIS`. Следуй локальной функции `pad()`:
данные выравниваются на 32 байта, четырёхбайтовая метка включена в промежуток.
Если до границы недостаточно места для метки, добавляется следующий блок.
Не заменяй это произвольным округлением смещений — такая ошибка уже ломала модель.

Вершины хранятся в общей системе модели, а обратная bind-матрица переводит их
в систему привязанной кости. Для текущих костей без исходного поворота матрица
содержит отрицательную абсолютную позицию. Если добавляешь исходные повороты,
нужно вычислять полноценные матрицы, а не оставлять только отрицательное смещение.

Индексы `uint16` адресуют диапазон 0…65535; текущий писатель ограничивает число
записей вершин значением 65535. Проверяй предел после экспорта/дублирования.
Все грани должны быть треугольниками с наружным обходом. Нормали, tangent и
bitangent должны быть согласованы с UV. Сглаживай соседние поверхности выборочно,
сохраняя жёсткие кромки и границы материалов.

## 5. SCA: локальные смещения и независимость наведения

SCA v5 использует заголовок `<4siifiiiii` длиной 40 байт, сигнатуру `ANIM`, списки
имён и родителей, затем данные анимации. Перед кадрами в `DATA` находятся 28 байт
позиции и quaternion корня. Каждый кадр содержит время и флаги (`<fi`, 8 байт),
затем по 28 байт (`<3f4f`) позиции и quaternion на каждую включённую кость.
Размер кадра — `8 + 28 × число костей`. Выравнивание секций такое же, как в SCM.

**Позиции в кадрах — локальные положения костей, а не нулевые добавки к bind-позе.**
Сохраняй базовые смещения во всех кадрах, даже если меняется только поворот.
Ранее запись `(0, 0, 0)` для каждой кости стянула модель и точку выстрела к основанию.

Имена анимационных костей должны совпадать с SCM. В клип можно включить только
нужную ветвь; включи необходимых родителей и пересчитай индексы родства внутри
списка SCA. Нельзя оставлять индексы из полного SCM при сокращённом списке костей.
Quaternions должны быть нормализованы, время кадров — согласовано с длительностью.

Для вращения кристалла и раскрытия стоек включай декоративные кости и корень.
**Не включай yaw, pitch и muzzle в декоративную idle-анимацию:** ими управляет
оружие. У текущей турели клипы содержат `GGA2301`, `Halo` и три `Fin*`.
Активация за секунду переводит стойки из наклона 5° в исходную позу; idle за 12 секунд
вращает кристалл и слегка меняет его высоту. Поза конца активации согласована
с началом idle. У циклического клипа проверяй совпадение поз на границе цикла.

## 6. UV, материалы и DDS

Рабочий набор состоит из albedo, SpecTeam и tangent-space normal map.
В примере все карты имеют размер 512×512, сжатие DXT5/BC3 и полную цепочку
из 10 mip-уровней до 1×1. Это рабочий вариант, не единственно допустимый размер.

| Карта / канал | Назначение |
| --- | --- |
| Albedo RGB | Основной рисунок и цвет материала |
| SpecTeam R | Интенсивность отражения окружения |
| SpecTeam G | Блик от солнечного освещения |
| SpecTeam B | Яркость для свечения / bloom |
| SpecTeam A | Маска цвета игрока |
| Normals RGB | Нормаль в пространстве касательных; ровная карта `(128, 128, 255)` |

Для призмы и световых полос используй маску цвета игрока; для неподвижного металла
маска обычно нулевая. Тонкие плавные линии можно хранить в альфе SpecTeam поверх
металлической окраски. Не заполняй маской весь атлас, если весь корпус не должен
перекрашиваться. Не путай альфу SpecTeam с прозрачностью материала.

По уточнению пользователя от 20 октября 2026 года корпуса Seraphim должны выглядеть
как блестящий металл; цвет игрока наносится на линии и узоры. Локальные примеры:
`source-assets/GGA2301/reference-seraphim-materials-01.png` и `-02.png` в моде
`seraphim-rework`. В них видны парные контуры и вложенные овалы на серебристых
поверхностях. Для GGA2301 заменены золотистые рамки и матовый синий каркас на
серебро/хром и отражающий тёмный металл. Узор хранится в альфе SpecTeam, а его
неглубокая гравировка — в normal map. Плиты между линиями не перекрашиваются;
призма сохраняет отдельно заданный для неё цвет игрока.

У структурных участков этой версии R SpecTeam составляет примерно 210–251,
G — 212–246; эти величины служат отправной точкой, а не универсальными константами
Seraphim. Блеск должен обеспечиваться реальными каналами отражения и блика,
а не нарисованными белыми пятнами в albedo. Для окрашенных линий на металле B
оставлен нулевым; яркость задана отдельно световым вставкам и кристаллу.

Сделай отдельные области атласа для брони, тёмных механизмов, кромок, кристалла
и световых вставок. Оставляй поля между областями для уменьшения перетекания цвета
на mip-уровнях. На длинной стойке UV должны идти непрерывно вдоль поверхности;
отображение тонкого узора на слишком узкую часть UV превращает его в широкое пятно.

Световая вставка должна физически выходить из своего кожуха. Уже встречалась
ошибка: после уменьшения толщины полосы она оказалась внутри более толстого
металлического корпуса и стала невидимой при корректном отсечении граней.

Стандартный `Unit` в этой реализации показывает кристалл как непрозрачную
гранёную поверхность с цветом игрока и яркостью. Стеклянное преломление из
референса здесь не реализовано; не обещай его только на основании красивого рендера.

## 7. Подключение к моду

Уточнение художественного стиля для GGA2401 от 20 октября 2026 года: пользователь
предоставил новые изображения и попросил застарелый тёмный металл вместо прежнего
слишком светлого, узоры «круги на полях», остроконечные левитирующие скалы,
раздвоенные клиновидные орудия и лепестковое/остроконечное основание. Для этого
юнита эти референсы заменяют прежние серебристые диски и тубусы. Изображения
сохранены в `source-assets/GGA2401/reference-*.png`; его материалы и геометрию
не следует автоматически переносить на другие модели. Цвет игрока по-прежнему
задаётся тонкими линиями SpecTeam, а не сплошной окраской всего металла.

Игровые файлы размещай в `mods/<slug>/units/<id>/`. У GGA2301 это два `_lod*.scm`,
два `.sca`, три `.dds`, `_mesh.bp`, `_unit.bp` и `_script.lua`. Авторские PNG,
OBJ/MTL, генераторы, референсы и архивы остаются в `source-assets/<id>/`.

В `Display.MeshBlueprint` указан виртуальный путь к mesh blueprint без `.bp`.
В нём для каждого LOD заданы `MeshName`, `AlbedoName`, `SpecularName`, `NormalsName`
и расстояние `LODCutoff`. Рабочий вариант для Seraphim использует `ShaderName = 'Unit'`
и `LookupName = '/textures/environment/Falloff_seraphim_lookup.dds'`.
Для других фракций не переноси Seraphim lookup автоматически.

Посмотри реальные файлы привязки:

- [GGA2301_mesh.bp](../mods/seraphim-rework/units/GGA2301/GGA2301_mesh.bp)
- [GGA2301_unit.bp](../mods/seraphim-rework/units/GGA2301/GGA2301_unit.bp)
- [GGA2301_script.lua](../mods/seraphim-rework/units/GGA2301/GGA2301_script.lua)

Анимация не запускается самим наличием SCA: скрипт создаёт `CreateAnimator`,
добавляет его в `Trash`, проигрывает активацию и затем idle. При изменении механики
проверяй необходимые вызовы по соответствующему локальному примеру/исходнику FAF.

При переносе в новый мод скопируй нужные авторские инструменты внутрь его
`source-assets`, замени ID, корневую кость, пути и настройки. Не импортируй во время
игры код или ресурсы из другого мода без явно оформленной зависимости.
Первичную установку выполняй целой папкой мода с `mod_info.lua` в корне.
При уже установленной копии и явно согласованной синхронизации ресурсов обновляй
именно её, проверяя совпадение файлов; не путай её с рабочей копией.

Локальные каталоги этого проекта:

```text
Рабочая копия:       D:\Games\FafModsCreate\mods\seraphim-rework
Установленная копия: D:\Games\FAF Mods\mods\seraphim-rework
```

## 8. Проверка результата

Сначала выполняй узкие проверки готовых файлов, без новой тестовой инфраструктуры:

1. Прочитай экспортированный SCM обратно: заголовок, смещения, имена костей,
   родителей, число вершин и индексов. Проверь конечные числа, индексы в пределах
   массива, ненулевую площадь треугольников, нормализованные нормали и согласованный
   tangent basis. Сверь одинаковый скелет у всех LOD.
2. Проверь SCA: имена и родство, размер кадров и файла, сохранение локальных позиций,
   нормализацию quaternion, переход activation → idle и границу цикла. Убедись,
   что декоративные клипы не содержат костей наведения.
3. Открой DDS реальным декодером, например Pillow. Проверь размер, mip-цепочку,
   маску цвета игрока и соответствие выбранных UV областям материалов.
4. Отрендери именно экспортированный SCM с отсечением обратных граней. Посмотри
   минимум фронтальный, боковой и верхний ракурсы; проверь альтернативный цвет игрока.
   Локальный рендер использует исходные PNG и приближённое освещение, поэтому
   отражения, DDS-сжатие и bloom в игре могут выглядеть иначе.
5. После установки сравни SHA256 ресурсов в рабочей и установленной копиях.
   Затем в локальном матче проверь загрузку, масштаб, материалы, раскрытие,
   idle, поворот, наклон, выпуск выстрела и переключение LOD. При ошибках смотри лог.

Проверка структуры и предпросмотр не подтверждают запуск в игре. На момент записи
этого руководства файлы последней пересборки прошли структурные проверки и получили
положительный отзыв пользователя по внешнему виду; фактический запуск этой версии
в локальном матче не подтверждён. Предыдущая версия имела подтверждение пользователя
о нормальной работе модели после исправления смещений SCA.

## 9. Быстрая диагностика

| Симптом | Что проверить сначала |
| --- | --- |
| Части съехали к основанию | Локальные позиции в каждом кадре SCA, inverse bind, иерархию |
| Выпуск выстрела у земли | Позицию и родителя muzzle, её имя в blueprint, влияние анимации, масштаб |
| Наведение сбрасывается | Не ключует ли idle кости yaw/pitch/muzzle |
| Поверхности пропали с одного ракурса | Обход треугольников, толщину геометрии и back-face culling |
| Металл выглядит ломаным | Нормали, сглаживание, tangent basis, совпадение UV и нормалей |
| Световая полоса исчезла | Не утоплена ли она в кожухе; корректны ли SpecTeam и UV |
| Узоры стали пятнами | Диапазон UV на конкретной грани и маску SpecTeam |
| Всё здание перекрашивается | Альфу SpecTeam и перетекание соседних участков атласа |
| Модель слабо похожа на референс | Пропорции, силуэт, настоящие проёмы и крупные объёмы до текстур |
| В игре видна старая версия | Виртуальные пути, каталог активного мода, хеши установленной копии и загрузку ресурсов в новом матче |

## 10. Источники для уточнений

При сборке GGA2401 дополнительно подтверждено по локальному FAF 3839 и upstream
`lua/sim/weapons/DefaultProjectileWeapon.lua`: ненулевой `RackRecoilDistance`
вместе с ненулевым `MuzzleSalvoDelay` вызывает ошибку и прерывает настройку оружия.
Для последовательного залпа используй `RackRecoilDistance = 0`. При положительном
`MuzzleSalvoDelay` цикл делает `MuzzleSalvoSize` выстрелов, перебирая `MuzzleBones`
по кругу; повторение имён позволяет задать порядок вроде `1,1,2,2,…`. Для GGA2401
подготовлены собственные SCM и предпросмотры, но запуск в матче не выполнялся.

в Интернете перед каждой похожей моделью не требуется.
